── First-Run ─────────────────────────────────────────────────────────────────

On fresh install with an empty database, the UI shows a banner directing you to
Settings → Job Templates. Configure at least one template to enable dispatch.

To migrate config from an existing instance:
  1. Export:  curl -H "Authorization: Bearer $AGENT_API_KEY" https://OLD_HOST/api/config/export > config.json
  2. Import:  curl -X POST -H "Authorization: Bearer $AGENT_API_KEY" \
                   -F "file=@config.json" https://NEW_HOST/api/config/import
  WARNING: import is destructive — it clears existing config before importing.

── Kubernetes Operations ─────────────────────────────────────────────────────

Agent Jobs are created by the Pipeline API. Job naming: caa-{workItemId[0:8]}

View active agent jobs:
  kubectl get jobs -l app.kubernetes.io/managed-by=caa-orchestrator -n {{ .Release.Namespace }}

Leader election Leases:
  kubectl get lease -n {{ .Release.Namespace }}

{{- if .Values.credentialPools.kiro }}
PVC Pool (kiro credentials):
  Configured PVCs: {{ join ", " .Values.credentialPools.kiro }}
  Dispatch claims an available PVC per kiro Job.
  If pool is exhausted, Jobs wait (stay Pending) until a PVC is released.
  PVCs must use ReadWriteOnce or ReadWriteOncePod access mode.
{{- end }}

Backup: run pg_dump against the database before upgrading. A helm rollback restores
images and values but cannot undo applied schema migrations.

── Job Controller ────────────────────────────────────────────────────────────

Service: {{ include "coding-agent-automation.fullname" . }}-jobcontroller:{{ .Values.jobController.service.port }}

Readiness check (must return 200 within 60 seconds after deploy):
  kubectl exec -n {{ .Release.Namespace }} <jobcontroller-pod> -- \
    curl -s -o /dev/null -w "%{http_code}" http://localhost:{{ .Values.jobController.service.port }}/readyz
  Expected: 200. If 503: leader election not yet complete, retry. If CrashLoopBackOff:
  check logs for fast-fail messages (missing PipelineApi:BaseUrl, AGENT_API_KEY, or not-in-cluster).

Job-templates ConfigMap changes take effect after a rollout (templates load once at startup):
  kubectl rollout restart deployment/{{ include "coding-agent-automation.fullname" . }}-jobcontroller -n {{ .Release.Namespace }}
{{- end }}
