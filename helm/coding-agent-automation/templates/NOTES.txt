── First-Run ─────────────────────────────────────────────────────────────────

On fresh install with an empty database, the UI shows a banner directing you to
Settings → Job Templates. Configure at least one template to enable dispatch.

To migrate config from an existing instance:
  1. Export:  curl -H "Authorization: Bearer $AGENT_API_KEY" https://OLD_HOST/api/config/export > config.json
  2. Import:  curl -X POST -H "Authorization: Bearer $AGENT_API_KEY" \
                   -F "file=@config.json" https://NEW_HOST/api/config/import
  WARNING: import is destructive — it clears existing config before importing.

agents[] → jobTemplates[] migration:
  The agents[] values section is removed. Define agent pod specs in jobTemplates[].
  See values.yaml for the jobTemplates schema.

── Kubernetes Operations ─────────────────────────────────────────────────────

Agent Jobs are spawned by the DispatchService. Job naming: caa-{workItemId[0:8]}

View active agent jobs:
  kubectl get jobs -l app.kubernetes.io/managed-by=caa-orchestrator -n {{ .Release.Namespace }}

View pending work items (via orchestrator logs):
  kubectl logs deployment/{{ include "coding-agent-automation.fullname" . }}-orchestrator -n {{ .Release.Namespace }} | grep "Pending"

Leader election Lease:
  kubectl get lease -n {{ .Release.Namespace }}

RBAC: The orchestrator ServiceAccount has permissions for:
  - Jobs (create/get/list/watch/delete)
  - Leases (create/get/update)
  - Secrets (create/delete — per-job credential injection)
  - Pods (get/list — startup failure detection)

{{- if .Values.credentialPools.kiro }}
PVC Pool (kiro credentials):
  Configured PVCs: {{ join ", " .Values.credentialPools.kiro }}
  DispatchService claims an available PVC per kiro Job.
  If pool is exhausted, Jobs wait (stay Pending) until a PVC is released.
  PVCs must use ReadWriteOnce or ReadWriteOncePod access mode.
{{- end }}

── Rollback Procedure ────────────────────────────────────────────────────────

export-config is a backup tool — it exports DB state to JSON files for safekeeping.
To export the current DB state:
  kubectl exec deployment/{{ include "coding-agent-automation.fullname" . }}-orchestrator -n {{ .Release.Namespace }} -- \
    dotnet CodingAgentWebUI.dll export-config --output /tmp/pipeline-export

Then copy out:
  kubectl cp {{ .Release.Namespace }}/$(kubectl get pod -l app.kubernetes.io/component=orchestrator -n {{ .Release.Namespace }} -o jsonpath='{.items[0].metadata.name}'):/tmp/pipeline-export ./pipeline-backup

To roll back to a previous version: restore from backup using the import endpoint (see First-Run above).

── Upgrade Notes ─────────────────────────────────────────────────────────────

Let in-flight work finish before upgrading — there is no drain hook. Jobs already
dispatched run to completion regardless, but new dispatch is paused during the
rollout. For zero downtime, wait until WorkItems reach terminal state, then upgrade.

── Monitoring ────────────────────────────────────────────────────────────────

Health endpoints:
  Liveness:  /healthz (DB SELECT 1 on dedicated connection)
  Readiness: /readyz  (unhealthy on DB loss, recovers on reconnect)

Key metrics (OpenTelemetry):
  workitems_by_status                    — gauge by status and agent_selector
  workitems_pending_duration_seconds     — histogram
  dispatch_latency_seconds               — histogram
  dispatcher_last_poll_epoch_seconds     — gauge (staleness detection)
  credential_pool_available              — gauge (PVC pool headroom)
